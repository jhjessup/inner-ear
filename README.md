A local-only meeting recorder, transcriber, and summarizer for macOS. Everything runs on-device — no cloud, no accounts, no uploads. It's a terminal (TUI) app, not a GUI.

```
$ innerear tui
```

## Features

- **Records** microphone audio and, optionally, system audio (Zoom/Meet/Teams — anything playing through your Mac, captured via ScreenCaptureKit) as two independent local files.
- **Transcribes** on-device via [WhisperKit](https://github.com/argmaxinc/argmax-oss-swift) (Core ML Whisper — `whisperLargeV3Turbo` or `parakeet`).
- **Diarizes** speakers: your microphone channel is always "Speaker 1"; system audio is split into distinct remote speakers using [SpeakerKit](https://github.com/argmaxinc/argmax-oss-swift) (voice-based, on-device). If voice separation isn't available, it degrades gracefully to a single shared "Speaker 2 (Remote)" bucket rather than failing — see [`docs/adr/phase-4b-speakerkit-separation.md`](docs/adr/phase-4b-speakerkit-separation.md).
- **Summarizes** extractively — key points, decisions, and action items pulled from your own words, not generated by an LLM. No fabrication, no hallucination risk, because nothing is generated.
- **Exports** to Markdown, plain text, RTF, JSON, PDF, or SRT subtitles.

All of it works entirely offline once the on-device models are downloaded on first use. Nothing you record ever leaves your Mac — enforced architecturally, not just promised (see [Privacy](#privacy)).

## Requirements

- macOS 14+
- Swift 6 toolchain (Xcode 16+, or Command Line Tools — full Xcode is not required for the CLI/TUI, only if you later want to wrap it in a GUI app; see [`docs/XCODE_SETUP.md`](docs/XCODE_SETUP.md))

## Install & run

```bash
git clone https://github.com/jhjessup/inner-ear.git
cd inner-ear
swift build
swift run innerear tui
```

First launch will prompt for microphone (and, if you capture system audio, Screen Recording) permission, and downloads the WhisperKit/SpeakerKit Core ML models on first use — expect a pause and a real download the very first time you record or transcribe something.

### CLI subcommands

`innerear tui` is the primary interface. A handful of lower-level, non-interactive subcommands also exist for scripting:

```bash
innerear record --duration 30                        # record for a fixed duration (mic + system audio by default)
innerear transcribe <audio-file> --model parakeet     # transcribe a file directly (no diarization)
innerear export <transcript-id> --format markdown     # markdown | text | rtf | json | pdf | subtitles
```

Run `innerear --help` or `innerear <subcommand> --help` for the full flag list.

## Architecture

This project follows a strict subject-verb-object decomposition: data models are inert structs, all behavior lives in single-purpose protocol ("verb") services, each with exactly one concrete implementation and one fake for tests. See [`ARCHITECTURE.md`](ARCHITECTURE.md) for the full rationale — read it before contributing, it explains the convention every file in this codebase follows.

Design decisions with real tradeoffs (why diarization works the way it does, why summarization is extractive rather than generative) are recorded in [`docs/adr/`](docs/adr/) as they're made, not just implemented silently.

## Testing

```bash
swift test
```

Unit and service-level tests run against fakes — no real audio hardware, Core ML inference, or network access, per this project's test doctrine. A couple of tests (`RecordingStoreTests`) exercise real filesystem I/O against a temp directory, and `NoNetworkAccessTests` actively asserts the fake-backed pipeline makes zero network requests, enforcing the privacy guarantee rather than just assuming it.

CI (see the badge above) builds and tests on every pull request against `master`, plus a CLI smoke check (`innerear --version` / `--help` actually execute, not just compile). Core ML inference itself only runs for real on Mac hardware, which GitHub-hosted CI runners don't have — a human runs `scripts/verify-on-mac.sh` on real hardware after pulling a branch for that coverage; results are logged under [`docs/mac-verification/`](docs/mac-verification/) (internal development records, not required reading).

## Privacy

No network calls happen anywhere in the record → transcribe → diarize → summarize → export pipeline. This is an architectural constraint, not a preference, and it's the thing this project exists to guarantee — see `docs/adr/` and the test doctrine's mandatory test matrix for how that's enforced rather than just claimed.
